# 01 — Implementation Plan

> Project: **Clever AI Team** — Visual Graph Abstraction Canvas & Persona Modeling backend
> Scope of this delivery: **backend API only** (FastAPI), fully dockerized, deployed on Clever Cloud.

## 1. Goals

Build the server side of a dual-surface multi-agent platform:

1. **Administrative canvas backend** — persist and compile visual agent graphs
   (person nodes + directed communication edges) expressed as a JSON DSL.
2. **Consumer chat backend** — ChatGPT-style sessions bound to a compiled graph,
   with a **Magentic-One dual-ledger orchestrator** coordinating the team and a
   real-time SSE observability stream (ledgers, agent debates, final answer).
3. **Lifelong learning** — Voyager executable-skill compilation and ExpeL
   post-mortem reflection, both asynchronous.
4. **Tiered memory** — Redis working memory, PostgreSQL relational recall,
   pgvector semantic archival memory.

## 2. Non-goals (this phase)

- The two frontends (React Flow canvas studio, Next.js chat surface).
- Docker-in-Docker/gVisor sandboxing (Clever Cloud Docker apps cannot spawn
  nested privileged containers; the sandbox uses hardened subprocess isolation).
- Multi-region scaling, SSO, billing.

## 3. Verified constraints (from live infrastructure probing)

| Constraint | Value | Consequence |
|---|---|---|
| PostgreSQL | 18.4, `max_connections=225` | Pool: 2 + 3 overflow per worker, ≤ 9 workers ⇒ ≤ 45 conns |
| pgvector | 0.8.5 pre-installed | HNSW cosine indexes available |
| Existing DB content | PostGIS/tiger tables in `public` | All app tables isolated in schema `clever_ai` |
| Redis | 8.10.1, password auth, no TLS on the provided port | `redis://` URL, pooled, namespaced keys `cat:*` |
| Clever Cloud Docker | Single container, env-injected config, port 8080 | Gunicorn master inside the container provides multi-core |

## 4. Phase plan

### Phase 1 — Infrastructure & persistence
- `pyproject.toml` (Python 3.12), uv-managed venv.
- Typed settings via pydantic-settings, with Clever Cloud env aliases
  (`POSTGRESQL_ADDON_URI`, `REDIS_ADDON_HOST`, …).
- Async SQLAlchemy engine (asyncpg) with conservative pooling; sync engine for Alembic.
- Redis pool + `CacheService` (JSON get/set/mget/pipeline/incr).
- JSON structured logging with request/run correlation IDs.
- Error taxonomy + global exception handlers (stable error envelope).
- 11 ORM tables in schema `clever_ai`; Alembic autogenerated initial migration
  applied to the live database (HNSW indexes on both embedding columns).

### Phase 2 — DSL, persona assembly, memory
- `GraphDSL` Pydantic v2 document: metadata, orchestrator spec, node manifest
  (identity / psyche / ethics / brain / memory sub-blocks), directed edges.
- Graph compiler: structural validation (single orchestrator, orphan detection,
  reviewer-role compatibility, duplicate dispatch edges) + materialization into
  `person_nodes` / `graph_edges` rows; compiled DSL cached in Redis.
- Persona Assembly Engine: 5-priority context pipeline (P0 constitution →
  P1 identity → P2 ExpeL lessons → P3 Voyager skills → P4 working context).
- Constitutional interceptor: LLM audit + corrective re-prompt recovery loop.
- Memory service: pgvector cosine search with access-count bookkeeping,
  Redis short-term dialogue buffers per (session, node).

### Phase 3 — Orchestration engine
- LLM gateway on LiteLLM: multi-provider resolution (OpenAI, Anthropic, Groq,
  DeepSeek, OpenRouter, Gemini, Ollama, LiteLLM proxy), retries, cost tracking,
  deterministic mock fallback when no key is configured.
- Magentic-One orchestrator: Task Ledger planning (JSON), Progress Ledger
  execution, dialectical review routing over `dialectical_review` edges,
  stall detection + replanning, streaming final synthesis.
- Redis pub/sub event bus with replay log (SSE consumers work across workers).

### Phase 4 — Lifelong learning
- AST validator (import allowlist, forbidden calls/attributes).
- Sandbox: `python -I -S` subprocess, rlimits (AS/CPU/NPROC/FSIZE), import guard,
  wall-clock timeout, output caps.
- Skill service: registration w/ smoke test, vector retrieval, execution audit,
  auto-promotion/quarantine statistics.
- ExpeL worker: post-mortem queue (`post_mortem_jobs`), lesson distillation into
  `agent_memories(type=lesson)`, Voyager skill candidates compiled + verified.

### Phase 5 — API surface & deployment
- Routers: auth, graphs, personas, sessions, chat (SSE), skills, post-mortems,
  memory, health. OpenAPI 3.1 at `/docs` (Swagger UI) and `/redoc`.
- Dockerfile (multi-stage, non-root) + `gunicorn.conf.py` ((2×cores)+1 Uvicorn
  workers, capped) + entrypoint running Alembic then Gunicorn.
- End-to-end smoke test (24 checks) against the live add-ons.
- Deploy via `clever deploy`; verify `/health/ready` and `/docs`.

## 5. Architecture-to-requirement traceability

| Requirement (spec) | Implementation |
|---|---|
| Person node = identity + morals + behavior + spirit + experiences | `DSLPersonNode` sub-blocks → `person_nodes` columns → persona assembly P0/P1 |
| Decoupled brain assignment per node | `BrainBinding` (provider/model/temperature/top_p) → LLM gateway resolution |
| Skills used to answer when relevant | Vector skill retrieval in persona assembly + `use_skill` loop in agent runtime |
| Persons know their role/duty | Identity block always injected at P1 |
| Save graph as DSL | `POST /graphs/{id}/compile` (validate + persist + version bump) |
| All messages saved to DB/history/memory | Immutable `messages` ledger + Redis working memory + archival embeddings |
| Train on each communication | ExpeL post-mortem after every run + Voyager skill compilation |
| Orchestrator receives message, generates tasks, orchestrates | Task Ledger planning + Progress Ledger dispatch |
| Full-featured chat backend | Sessions, message history, SSE dual-stream, run replay |
| FastAPI on all CPU cores | Gunicorn (2×N)+1 Uvicorn workers, uvloop, ProcessPoolExecutor |
| Swagger UI | `/docs`, `/redoc`, OpenAPI 3.1 with tags/summaries/examples |
| PostgreSQL with vector feature | pgvector 0.8.5, HNSW cosine indexes, 1536-dim embeddings |
| Redis for speed everywhere | embeddings cache, DSL cache, working memory, event bus, locks, rate limits |
| Dockerized for Clever Cloud | Multi-stage Dockerfile, port 8080, env-driven config |
